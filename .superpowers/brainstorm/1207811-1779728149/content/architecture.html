Design: Kiến trúc tổng thể

Realtime Camera Management — Approach A: StreamerManager Actor

Các thành phần mới

Backend

StreamerManager

Actor Tokio nhận commands qua mpsc channel. Owns JoinSet + shutdown senders. Quản lý lifecycle của từng Streamer task.

Backend

REST API Endpoints

POST/PUT/DELETE /api/cameras và streams. Ghi DB, gửi command đến StreamerManager, trả về response.

Frontend

React UI /cameras

Trang quản lý camera: danh sách, form thêm/sửa/xóa. Pattern giống trang /users hiện tại.

Data Flow: Add Camera

React UI → POST /api/cameras → API Handler → db.add_camera() + db.add_stream() → StreamerManager
↓ StartStream(stream_id)
spawn Streamer task → kết nối RTSP → ghi DB
API Handler ← 201 Created ← (không chờ streamer connect)

Data Flow: Update Camera

React UI → PUT /api/cameras/{id} → API Handler → db.update_camera() → StreamerManager
↓ RestartStream(stream_id)
shutdown cũ → đợi task end → spawn mới
API Handler ← 200 OK

StreamerManager (Rust)

enum StreamerCommand {
  StartStream(i32),   // stream_id
  StopStream(i32),    // stream_id
  RestartStream(i32), // stream_id
}

struct StreamerManager {
  db: Arc<db::Database>,
  env: &'static Environment,
  rx: mpsc::Receiver<StreamerCommand>,
  running: HashMap<i32, base::shutdown::Sender>,
  join_set: JoinSet<()>,
}

API Handler nhận mpsc::Sender<StreamerCommand> qua web::Service — không cần share state khác. StreamerManager chạy trong task riêng, nhận lệnh và quản lý toàn bộ lifecycle.
